**Frontend conventions:**
- Server components by default; `"use client"` only on the files that use hooks / dnd-kit / React Query.
- HTTP: reuse the existing `src/lib/api.ts` axios instance — JWT is read from `localStorage.getItem("token")` and attached as `Authorization: Bearer …` on every request. Do not add a parallel fetch wrapper.
- Auth: `AuthContext` exposes `{ token, userId, userEmail, setToken, clearToken, registerWithEmail, loginWithEmail }`. The Phase 4 "Quick register (dev only)" home-page button is gone — `AuthScreen` is now the real sign-in / create-account UI, wired to `POST /api/auth/register` and `POST /api/auth/login`. The user snapshot returned by `getUserSnapshot` is **memoized at module scope keyed on the raw localStorage string** so `useSyncExternalStore`'s `Object.is` comparison sees a stable reference; a fresh `{ id, email }` literal on every call would trigger the "The result of getSnapshot should be cached to avoid an infinite loop" runtime error. (`getTokenSnapshot` returns a string and is already stable by value.)
- React Query: one `QueryClient` per browser tab is created in `src/app/providers.tsx` via a `useState` initializer. Default `staleTime: 30_000`, `refetchOnWindowFocus: false`.
- Optimistic updates: snapshot is captured at dnd-kit `onDragStart` into a `useRef` (preferred over the TanStack `onMutate` snapshot because the dnd-kit snapshot was taken before any `onDragOver` previews). Mutations roll back to that snapshot on error.
- Next.js 16: dynamic route `params` is `Promise<{ id: string }>` — pages must `await params`. `node_modules/next/dist/docs/` is the source of truth (the project's `AGENTS.md` warns that "this is NOT the Next.js you know").
- Icons: the `Icon` component (`features/board/components/Icon.tsx`) renders an inline-SVG Material Symbols silhouette. **Size icons with the `width` / `height` properties (Tailwind `w-* h-*` utilities) — never with `text-[Npx]`**. The Stitch HTML uses the text-size hack to drive its font-based icon glyphs; the inline-SVG component here doesn't, and `text-[Npx]` is silently ignored. When the Tailwind `@theme` size key isn't generated automatically, mirror it as an inline `style={{ width, height }}` for redundancy.
- **Motion language (Phase 5, planned; see `specs/Phase05/Plan.md` §3 + `Requirements.md` §4):** a new `src/design/motion.css` defines the tokens `--ease-standard: cubic-bezier(0.2, 0, 0, 1)`, `--ease-emphasized: cubic-bezier(0.3, 0, 0, 1)`, `--duration-fast: 120ms`, `--duration-medium: 200ms`, `--duration-slow: 320ms` (also exposed as Tailwind v4 `@theme` keys so `duration-(--duration-medium)` works without a config extension). The Phase 4 placeholder `<div role="status">` toast is promoted to a real `<Toast />` component (`features/board/components/Toast.tsx`) that slides in from the bottom-right, auto-dismisses after 4s, pauses on hover, exposes `role="status"` for screen readers, and is used by every new mutation hook for success and error reporting. The board view's initial mount does **not** animate; the dnd-kit `DragOverlay` keeps its built-in animation; the sidebar collapse uses `transition-[width] duration-(--duration-slow) ease-(--ease-standard)`. **No** `framer-motion` / `motion` is added.
- **Quick-add keyboard shortcut (Phase 5, planned; see `specs/Phase05/Plan.md` §6 + `Requirements.md` §7):** typing `c` while no input is focused on the board view opens a centered `<QuickAddTaskModal />` with a single `<input>` + a column `<select>`; the handler subscribes to `keydown` via a `useEffect` in `BoardView.tsx` and short-circuits if `e.target` is an `<input>` / `<textarea>` / `[contenteditable]`. A `?` help button in `BoardControlBar` opens a one-screen shortcut list (static `<dl>`). Stretch goals — `b` opens `CreateBoardDrawer`, `m` opens `ShareBoardModal` — ship only if the base shortcut lands first.
- `TaskModal` (`features/board/components/TaskModal.tsx`): presentation-only. The interactive fields (title edit, subtask add/toggle, comment post, status / priority / column / due date / assignees / labels / story-points) all live in local `useState`. **Phase 5 wiring (planned; see `specs/Phase05/Plan.md` §5 and `Requirements.md` §6.1) replaces the local setters with TanStack Query mutations** — `useUpdateTaskMutation` (debounced 600ms; PATCHes `PATCH /api/tasks/:id` with the relevant partial; the autosave footer's `Saving…` / `Saved` / `Failed to save` text reflects in-flight / settled state), `useCreateSubtaskMutation` / `useToggleSubtaskMutation` / `useCreateCommentMutation` (against the new `POST /api/tasks/:id/subtasks`, `PATCH /api/tasks/:id/subtasks/:subtaskId`, `DELETE /api/tasks/:id/subtasks/:subtaskId`, `POST /api/tasks/:id/comments` endpoints), `useUpdateTaskMutation` for the metadata sidebar (status / priority / column-via-`useMoveTaskMutation` / due date / labels / story points), and a two-step trash confirm (3s window; DELETE; toast with 5s `Undo` that re-creates the task from the cached pre-delete shape). Re-mount the component (parent uses a `key={task.id}`) rather than resetting local state on `open` transitions; the `setState-in-effect` anti-pattern is rejected by the project's ESLint config.
- `ShareBoardModal` (`features/board/components/ShareBoardModal.tsx`) + `CreateBoardDrawer` (`features/board/components/CreateBoardDrawer.tsx`): both are presentation-only overlays ported verbatim from `.stitch-cache/share.html` onto the Kinetic Grid tokens. `BoardView` owns the `shareModalOpen` / `createBoardOpen` flags (lifted to the board root so the body scroll-lock and Esc-to-close handlers don't need to be re-implemented) and passes opener callbacks (`onOpenShareModal`, `onOpenCreateBoard`) down to `BoardControlBar`. The two overlays accept optional callback props (`onSendInvite`, `onRemoveMember`, `onChangeMemberRole`, `onSave` for the modal; `onCreate` for the drawer). **Phase 5 wiring (planned; see `specs/Phase05/Plan.md` §5 and `Requirements.md` §6.2–6.3) wires these callbacks to the real backend:** `onSendInvite` → `POST /api/boards/:id/members` (widened body, role defaults to `MEMBER`); `onRemoveMember` → `DELETE /api/boards/:id/members/:userId`; `onChangeMemberRole` (staged, committed on Save Changes) → `PATCH /api/boards/:id/members/:userId` with `{ role: "MEMBER" | "ADMIN" }` (new endpoint, owner role immutable); the `linkSharing` toggle → `PATCH /api/boards/:id` with `{ linkSharing: "DISABLED" | "VIEW" }` (new `LinkSharing` enum field — if the public read endpoint is too big for Phase 5, the toggle ships as a no-op that toasts `Coming soon` and the gap is documented in `Validation.md` §12); `onCreate` → `POST /api/boards` with the widened body `{ title, projectKey (≤ 6 chars, uppercased server-side), colorIdentity, template }` followed by `router.push("/boards/:newId")`. Until then, `BoardView` surfaces a toast from each trigger so the controls feel real. The share modal reads `board.members` (from `useBoardQuery`) for the collaborators list and tags the current user's row with `(You)` (the user id is read from `useAuth()`). **Adding a new feature module** — create `src/modules/<name>/` with:
- `<name>.controller.ts` — HTTP I/O only (read `req`, call service, write `res`)
- `<name>.service.ts` — business logic (DB, hashing, external calls)
- `<name>.validation.ts` — `zod` schemas + inferred input types

- `index.ts` — barrel: `export { default as <name>Router } from "./<name>.routes.js"`

Then mount it in `src/app.ts` (e.g. `app.use("/api/<name>", <name>Router)`) and add the new env vars (if any) to the `EnvSchema` in `src/config/env.ts`. Optional: `PORT` (default 4000), `BCRYPT_SALT_ROUNDS` (default 12), `JWT_EXPIRES_IN` (default `7d`), `LOG_LEVEL` (default `info` — Phase 5 pino request-logger). The schema lives in `src/config/env.ts` (zod) — add new keys there, then read them off the typed `config` object. The full list is mirrored in `server/.env.example` (Phase 5 deployment-readiness); Phase 5's `audit-routes.mjs` cross-checks every `process.env.<X>` against the example file.
- The frontend `LayoutProps` type used in `src/app/layout.tsx` comes from Next.js 16's type system — do not shadow it.
- The server uses Prisma 7's driver-adapter pattern — import the client from `src/generated/prisma/client.js` (note the `.js` extension — required by `module: NodeNext`) and pass a `PrismaPg` adapter to `new PrismaClient({ adapter })`. Do not use the legacy `PrismaClient` constructor without an adapter.
- **ESM import rules** for the backend: every relative import must use the `.js` extension, and type-only imports must use `import type { ... }` (`verbatimModuleSyntax: true`). The on-disk source files are still `.ts`; only the import specifier changes.

## Deployment & CI (Phase 5, planned; see `specs/Phase05/Plan.md` §14 + `Requirements.md` §15)

- **`server/.env.example`** (Phase 5) mirrors every `process.env.<X>` consumed by `server/src/`: `DATABASE_URL` (required), `JWT_SECRET` (required; `openssl rand -hex 32` for production), `PORT` (default 4000), `BCRYPT_SALT_ROUNDS` (default 12), `JWT_EXPIRES_IN` (default `7d`), `LOG_LEVEL` (default `info` for the `pino` request logger). The `audit-routes.mjs` script cross-checks the example against the source.
- **`GET /health`** (Phase 1) returns 200 `{status: "ok", timestamp, db: "up"}` on a successful `SELECT 1`; 503 `{status: "degraded", timestamp, db: "down", error}` on failure. Sufficient for orchestrator liveness probes; Phase 5 only adds a documentation block to the route file.
- **GitHub Actions CI** (`.github/workflows/ci.yml`, Phase 5) — two jobs on `ubuntu-latest` with Node 22:
  - `lint-and-typecheck`: `cd server && npm ci && npm run lint` (which now also runs `audit-routes.mjs`); `cd client/kanban-board-client && npm ci && npm run lint && npx tsc --noEmit`.
  - `e2e`: a `postgres:16` service container; `cd server && npx prisma migrate deploy`; `npm start` in the background; all three `phase*-e2e.ps1` scripts and the `lexoPosition` smoke script run against the live dev server. PowerShell Core 7+ is preinstalled on the runner.
  - Triggers: PRs targeting `main` and pushes to `phase*` branches.
- **Husky + lint-staged** (Phase 5) — `.husky/pre-commit` runs `npx lint-staged`, which runs `eslint --fix` + `tsc --noEmit` on staged files in the matching project (`server/src/**/*.ts` → server; `client/kanban-board-client/src/**/*.{ts,tsx}` → client). The hook is fast (only staged files are touched); the full `tsc` / e2e suite stays in CI.
- **No Docker / containers** — services run directly on the host (consistent with the rest of the project). The CI Postgres service is the only exception and is a transient test container, not part of the project's runtime story.
