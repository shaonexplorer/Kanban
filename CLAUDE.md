**Frontend conventions:**
- Server components by default; `"use client"` only on the files that use hooks / dnd-kit / React Query.
- HTTP: reuse the existing `src/lib/api.ts` axios instance — the JWT lives in an httpOnly `token` cookie (Phase 5 Step 8) and the axios instance is configured with `withCredentials: true` so the browser attaches it to every cross-origin request automatically. The previous `Authorization: Bearer …` interceptor that read from `localStorage` was removed in Step 8; do not reintroduce it. Do not add a parallel fetch wrapper.
- Auth: `AuthContext` exposes `{ isAuthenticated, userId, userEmail, registerWithEmail, loginWithEmail, signOut }` (Phase 5 Step 8). The previous `token` / `setToken` / `clearToken` shape (and the `localStorage` / `useSyncExternalStore` plumbing behind it) is gone — the JWT lives in an httpOnly `token` cookie the client cannot read, and the only boolean the context can compute is `isAuthenticated`. Identity is fetched on demand from `GET /api/auth/me` on first mount and re-fetched after every login / logout via a `kanban-auth-change` custom event; cross-component sync stays in plain DOM events (no external state library, no `useSyncExternalStore`). `signOut()` calls `POST /api/auth/logout` (server clears the cookie), clears the local identity snapshot, broadcasts the auth change, and returns; navigation to `/` is the caller's responsibility (the sidebar and `EmptyBoardsState` both call `signOut() + router.replace("/")`). `BoardViewGate` and the home page gate on `isAuthenticated` instead of a token value. The Phase 4 "Quick register (dev only)" home-page button is gone — `AuthScreen` is the real sign-in / create-account UI, wired to `POST /api/auth/register` and `POST /api/auth/login`.
- React Query: one `QueryClient` per browser tab is created in `src/app/providers.tsx` via a `useState` initializer. Default `staleTime: 30_000`, `refetchOnWindowFocus: false`.
- Optimistic updates: snapshot is captured at dnd-kit `onDragStart` into a `useRef` (preferred over the TanStack `onMutate` snapshot because the dnd-kit snapshot was taken before any `onDragOver` previews). Mutations roll back to that snapshot on error.
- Next.js 16: dynamic route `params` is `Promise<{ id: string }>` — pages must `await params`. `node_modules/next/dist/docs/` is the source of truth (the project's `AGENTS.md` warns that "this is NOT the Next.js you know").
- Icons: the `Icon` component (`features/board/components/Icon.tsx`) renders an inline-SVG Material Symbols silhouette. **Size icons with the `width` / `height` properties (Tailwind `w-* h-*` utilities) — never with `text-[Npx]`**. The Stitch HTML uses the text-size hack to drive its font-based icon glyphs; the inline-SVG component here doesn't, and `text-[Npx]` is silently ignored. **Adding a new feature module** — create `src/modules/<name>/` with:
- `<name>.controller.ts` — HTTP I/O only (read `req`, call service, write `res`)
- `<name>.service.ts` — business logic (DB, hashing, external calls)
- `<name>.validation.ts` — `zod` schemas + inferred input types
- `<name>.routes.ts` — `Router` that wires `validate(schema, "body" | "params") → [loadBoard|loadColumn|loadTask → requireBoardAccess|requireBoardOwner →] asyncHandler(controller.fn)`
- `index.ts` — barrel: `export { default as <name>Router } from "./<name>.routes.js"`

Then mount it in `src/app.ts` (e.g. `app.use("/api/<name>", <name>Router)`) and add the new env vars (if any) to the `EnvSchema` in `src/config/env.ts`. Throw `HttpError(status, message)` from the service to surface domain errors through the central error middleware. On `:id` routes that resolve to a board-scoped resource, use the deepest applicable loader: `loadBoard` for board routes, `loadColumn` for column routes (auto-exposes `req.board`), or `loadTask` for task routes (auto-exposes `req.board` and `req.column`) — never re-query the parent inside the controller. **Phase 4 move endpoints** (Steps 3 and 4, Float-simplified in Phase 5) wrap their writes in `prisma.$transaction` and use `floatPosition` (in `src/common/utils/floatPosition.ts`) to compute new positions — never produce or compare `position` numbers inline. All integer-arithmetic call sites have been replaced; `npx tsc --noEmit` is clean.

## Deployment & CI (Phase 5, planned; see `specs/Phase05/Plan.md` §14 + `Requirements.md` §15)

- **`server/.env.example`** (Phase 5) mirrors every `process.env.<X>` consumed by `server/src/`: `DATABASE_URL` (required), `JWT_SECRET` (required; `openssl rand -hex 32` for production), `PORT` (default 4000), `BCRYPT_SALT_ROUNDS` (default 12), `JWT_EXPIRES_IN` (default `7d`), `LOG_LEVEL` (default `info` for the `pino` request logger). The `server/scripts/audit-routes.mts` script (Phase 5 Step 7, done) runs as part of `npm run lint` and walks the live Express route table; it is the formal gate for the input-validation audit.
- **`GET /health`** (Phase 1) returns 200 `{status: "ok", timestamp, db: "up"}` on a successful `SELECT 1`; 503 `{status: "degraded", timestamp, db: "down", error}` on failure. Sufficient for orchestrator liveness probes; Phase 5 only adds a documentation block to the route file.
- **GitHub Actions CI** (`.github/workflows/ci.yml`, Phase 5) — two jobs on `ubuntu-latest` with Node 22:
  - `lint-and-typecheck`: `cd server && npm ci && npm run lint` (which now also runs `audit-routes.mts` after `tsc --noEmit`); `cd client/kanban-board-client && npm ci && npm run lint && npx tsc --noEmit`.
  - `e2e`: a `postgres:16` service container; `cd server && npx prisma migrate deploy`; `npm start` in the background; all three `phase*-e2e.ps1` scripts run against the live dev server. PowerShell Core 7+ is preinstalled on the runner. (The `lexoPosition` smoke script was removed in the Phase 5 Float follow-up; Float ordering is exercised by the e2e scripts.)
  - Triggers: PRs targeting `main` and pushes to `phase*` branches.
- **Husky + lint-staged** (Phase 5) — `.husky/pre-commit` runs `npx lint-staged`, which runs `eslint --fix` + `tsc --noEmit` on staged files in the matching project (`server/src/**/*.ts` → server; `client/kanban-board-client/src/**/*.{ts,tsx}` → client). The hook is fast (only staged files are touched); the full `tsc` / e2e suite stays in CI.
- **No Docker / containers** — services run directly on the host (consistent with the rest of the project). The CI Postgres service is the only exception and is a transient test container, not part of the project's runtime story.
